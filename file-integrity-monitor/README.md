# File Integrity Monitor (FIM)

A Linux file-integrity monitor that establishes a trusted **baseline** of files, detects
unexpected changes, and produces **evidence-backed alerts** (JSON, CSV, text, RFC 5424 syslog,
CEF). Python core (Pydantic, Typer), Bash operational helpers, optional Ed25519-signed baselines
and optional inotify-based monitoring.

* Read-only with respect to monitored files: it **never modifies or restores them**.
* Never mistakes "couldn't look" for "clean": unreadable, vanished, racing, oversized or
  unlistable paths make the scan **INCOMPLETE** (exit 3).
* Baselines are versioned, written atomically, stored outside monitored roots with `0700/0600`
  modes, integrity-checked, optionally signed, and every update is audited (hash-chained).
* Honest about limits: local hashing cannot protect a host whose attacker controls the signing
  key. See [docs/security-and-limitations.md](docs/security-and-limitations.md).

## Quick start

```bash
cd file-integrity-monitor
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements.lock && .venv/bin/pip install --no-deps -e .
source .venv/bin/activate
scripts/demo.sh            # self-contained demo in a temp workspace; cleans up after itself
```

Then follow the [walkthrough](docs/walkthrough.md).

## Command overview

```text
fim config check | baseline create/update/verify/list/show | scan | report convert
fim keygen | sign | audit show/verify | watch | version
```

Exit codes: `0` clean · `1` findings · `2` usage/config · `3` incomplete scan · `4` baseline untrusted ·
`5` export failure · `6` operational error. Details: [user-guide.md](docs/user-guide.md#exit-codes).
